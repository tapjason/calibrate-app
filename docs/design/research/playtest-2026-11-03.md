# Blind playtests (November 2026, second round)

## Method

Same as the 2026-11-01 round (`playtest-2026-11-01.md`). Each run was a fresh agent
with only the Playwright browser tools: no repo, no docs, and a persona, tasks and a
fixed report format. The runs went one after another, since they share a browser.
Run 1 started from a freshly cleared install. Run 2 loaded the demo data, and
runs 3 and 4 kept what earlier runs left. Screenshots are in
`.playwright-mcp/playtest-2026-11-03/` (gitignored). No run signed in, bought
anything or erased data. Run 1 opened one of its own screenshots; no other file was
read.

**The name.** Nothing on screen called the app anything else: the page title, the
card footers, "Fairly Sure Plus" and "Everything Fairly Sure sends" all used the new
name. "Fairly Sure Plus" wraps to two lines on the paywall at 320 px, which is
fine. Run 1 read it as "casual, a bit hedgy, like a shrug" at first, and afterwards
said it fits, since every screen asks how sure you are. Run 4 said it's modest and
fits calibration: the "credential feel" comes from "87/100", "Sharp" and "Oracle"
on the card, not from the name. Run 1 noted that "calibration" is still everywhere
("Calibrating", "calibration rating", "My calibration warm-up"), which the name
seemed meant to avoid.

**What landed.** The D34 correction window ("Until 1:10 AM tomorrow you can change
the answer…", one tap). D39 and D40: "Family" with a ZWJ family emoji in under a
minute, shown on Log, Today and Insights. The D38 times and digest day, with
captions in words. D37's "Furthest off: finance", which Priya believed. Every number
Sam recomputed matched: the band counts, the 87 rating, Brier 0.22 against a 0.23
base-rate baseline, the 80% grey bars, the D35 low-end badge rule and "since last
week". No console errors from app code.

### Web only (matter if the web build becomes the web Warmup, FUTURE_UI A8)
- Hidden tab screens stay in the Tab order (26 stops), so focus disappears behind
  the visible tab. Recurs from 2026-11-01.
- Space doesn't pick a custom radio (Log's categories, the emoji grid); arrows don't
  move inside a radiogroup; Escape doesn't close a sheet; focus falls to `<body>`
  after Save, after a sheet closes and after "Use the default". The confidence
  slider can't be focused.
- Every heading is level 1; the emoji radios carry no checked state; the chart's
  axis labels are read twice; Share's tabs have no tablist.

## Test artefacts, not app faults

- **The icon picker "stuck" after cancelling "Choose a picture"** (run 2). The web
  picker resolves on the browser's `cancel` event, which Safari and Chrome send
  when the file dialog is dismissed. Playwright's cancel doesn't send it. When the
  event was dispatched by hand, the picker came back at once. On iOS the native
  picker returns "cancelled".
- "Personal: a score above 85 to reach Sharp" without "even at its low end" (runs 2,
  3, 4) is deliberate. The clause appears only when the score clears the bar and
  only its give-or-take falls short (`CategoryBadge.progressHint`). Personal's 83 is
  under 85.
- "8 of 17 happened. About 45% would have matched": the suggested confidence is
  rounded to 5 on purpose. It isn't the share that happened.
- Console errors in run 4's full log ("PLUS_NAME is not defined", a merge marker,
  `chartTakeaway.ts`) date from mid-edit moments before the run, and didn't recur.
- The black lightning-bolt square is the development build's tools menu.
- A +5 from an empty Warm-up control landing on 80% is D36: the first step goes from
  where the resting thumb shows.
